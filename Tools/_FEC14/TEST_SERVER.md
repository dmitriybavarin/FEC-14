# Тестовый сервер FEC-14 для игроков

Инструкция поднимает отдельный сервер, на который игроки заходят через обычный лаунчер SS14 и проверяют новую сборку. Основной сервер при этом не трогается.

По [лицензии](../../LICENSE.TXT) любой сервер, куда заходят посторонние игроки, считается публичным, даже тестовый и бесплатный. Поднимать его можно только с письменного разрешения владельца проекта. Локальный сервер для себя и своих разработчиков разрешения не требует.

## 1. Что нужно

- Компьютер или VPS с Windows или Linux (x64), 4 ГБ памяти и больше, 2+ ядра.
- [.NET Runtime 9](https://dotnet.microsoft.com/download/dotnet/9.0) на машине сервера. Сборка не self-contained, без рантайма сервер не запустится.
  Пока движок на версии 264 (`python Tools/_FEC14/engine.py status`), нужен именно .NET 9. После перехода на движок 269+ понадобится .NET 10.
- Открытый порт **1212** и по **TCP**, и по **UDP** (TCP нужен для страницы статуса и скачивания клиента, UDP для самой игры).
- На машине, где собирается сборка: репозиторий FEC-14 и .NET SDK из `global.json`.

## 2. Собрать сборку

В VS Code: задача **FEC: Упаковать сервер (Release, win-x64)**. Или в консоли из корня репозитория:

```
dotnet run --project Content.Packaging server --hybrid-acz --platform win-x64
```

Для Linux-сервера вместо `win-x64` указать `linux-x64`. Готовый архив появится в `release/SS14.Server_<платформа>.zip`.

`--hybrid-acz` обязателен: с ним сервер сам раздает игрокам клиентскую часть (FEC-контент), отдельный хостинг файлов не нужен. Движок лаунчер игрока скачивает сам по версии, которую сообщает сервер.

## 3. Развернуть

1. Распаковать архив в отдельную папку, например `C:\FEC14-test` или `/opt/fec14-test`.
2. Положить рядом с `Robust.Server(.exe)` файл `server_config.toml`. Взять его из `Tools/_FEC14/CONFIG.template/server_config.toml` и поменять:

```toml
[net]
port = 1212

[status]
connectaddress = "ss14://IP_ИЛИ_ДОМЕН:1212"

[game]
hostname = "FEC-14 [ТЕСТ]"
desc = "Тестовый сервер. Возможны ошибки и вайпы."

[hub]
advertise = false

[auth]
mode = 1

[console]
loginlocal = false

[whitelist]
enabled = true
prototype_list = "basicWhitelist"

[database]
engine = "sqlite"
sqlite_dbpath = "preferences.db"

[fec]
ooc_colors_file = "ooc_colors.json"
```

- `hub.advertise = false`: сервер не виден в общем списке, зайти можно только по адресу. Для открытого теста поставить `true` и заполнить `[hub] server_url` тем же адресом, что в `connectaddress`.
- `auth.mode = 1`: вход только через аккаунт SS14. Не ставить `0` или `2` на публичном сервере, иначе любой сможет зайти под чужим ником.
- `whitelist.enabled = true`: на закрытый тест пускать только тех, кого добавили.
- Токены Discord, пароли базы и вебхуки основного сервера в тестовый конфиг не копировать.

## 4. Открыть порт

Windows (PowerShell от администратора):

```
New-NetFirewallRule -DisplayName "FEC14 test TCP" -Direction Inbound -Protocol TCP -LocalPort 1212 -Action Allow
New-NetFirewallRule -DisplayName "FEC14 test UDP" -Direction Inbound -Protocol UDP -LocalPort 1212 -Action Allow
```

Linux (ufw):

```
sudo ufw allow 1212/tcp
sudo ufw allow 1212/udp
```

Если сервер дома за роутером, на роутере пробросить 1212 TCP и UDP на этот компьютер.

## 5. Запустить

Windows: `Robust.Server.exe`. Linux:

```
chmod +x Robust.Server
./Robust.Server
```

На Linux удобнее держать сервер службой systemd или в `tmux`, чтобы он не закрывался вместе с SSH.

Проверка: открыть в браузере `http://IP:1212/info`. Там должен быть JSON, а `build.engine_version` должен совпадать с версией из `engine.py status` (сейчас `264.0.2-fix-physics`). Если версия без суффикса, игроки получат ошибку `Failed to deserialize MsgConVars`.

## 6. Админка и доступ игроков

В консоли сервера (окно, где он запущен):

```
promotehost <свой ник>
whitelistadd <ник игрока>
```

`promotehost` выдает полные права админа до перезапуска. Постоянные права выдаются через админ-меню в игре или в базе.

Игроки заходят так: лаунчер SS14, кнопка **Direct Connect**, адрес `ss14://IP_ИЛИ_ДОМЕН:1212`. Первый вход дольше обычного: лаунчер качает движок и клиент FEC-14.

## 7. Обновить тестовую сборку

1. Собрать новый архив (шаг 2).
2. Остановить сервер командой `shutdown` в консоли.
3. Удалить из папки сервера все, кроме `server_config.toml`, `preferences.db`, `ooc_colors.json` и папки `logs`, распаковать новый архив поверх.
4. Запустить снова. Игрокам достаточно переподключиться, лаунчер сам скачает изменения.

Перед обновлением с изменениями базы данных сделать копию `preferences.db`.

## 8. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Лаунчер не видит сервер, `/info` не открывается | Закрыт TCP 1212 или неверный `connectaddress`. |
| Подключение висит на "Connecting" | Закрыт UDP 1212. |
| `Failed to deserialize MsgConVars` | Версия движка у сервера и клиента разная. Проверить `build.engine_version` в `/info`. |
| `You are not on the whitelist` | Игрока нет в списке: `whitelistadd <ник>`. |
| Сервер сразу закрывается | Не установлен .NET Runtime нужной версии или занят порт. Смотреть последний файл в `logs`. |

## 9. Безопасность

- Не запускать сервер от администратора или root, лучше отдельный пользователь.
- `console.loginlocal = false` на сервере, к которому есть удаленный доступ: иначе любой, кто подключился с самой машины, получает права хоста.
- Не публиковать `server_config.toml` с паролями и токенами.
- Держать ОС и .NET Runtime обновленными, наружу открывать только порт 1212.
