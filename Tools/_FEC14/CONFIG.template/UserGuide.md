## Быстрый старт

1. Задача **FEC: Восстановить .CONFIG + проверки**: создаст пустой `.CONFIG/` и проверит его.
2. Заполнить `.CONFIG/server_config.toml` (порт, название, база, вебхуки).
3. Собрать (**Собрать DEV** или **Собрать Release**) и запустить сервер и клиент.

## Задачи VS Code

| Задача | Что делает |
|---|---|
| Собрать DEV / Собрать Release | собирает всё решение в Debug / Release |
| Сервер DEV / Клиент DEV | запускает без пересборки, нужна предварительная сборка DEV |
| Сервер Release / Клиент Release | запускает без пересборки, нужна предварительная сборка Release |
| Восстановить .CONFIG + проверки | пересоздаёт пустой `.CONFIG` из шаблона и запускает проверки |

То же из консоли: `python Tools/_FEC14/init_cfg.py --reset --check`.

## Папка `.CONFIG`

Папка в `.gitignore`: токены и пароли в git не попадут.

Шаблон `.CONFIG` лежит в `Tools/_FEC14/CONFIG.template/`. Без `--reset` существующие файлы не перезаписываются. С `--reset` старый `.CONFIG` сохраняется как `.CONFIG.backup-*` (тоже в `.gitignore`), удалить его можно вручную.

| Файл | Кто читает | Что внутри |
|---|---|---|
| `.CONFIG/server_config.toml` | сервер (`--config-file`) | порт, название, хаб, база данных, вебхуки Discord, ссылки, секция `[fec]` |
| `.CONFIG/ooc_colors.json` | сервер | цвета ников в OOC по GUID |
| `.CONFIG/admin_weights.json` | сервер | вес админ-рангов (`fec.admin_weights_file`) |

## Настройки FEC14

Секция `[fec]` в `server_config.toml`:

| Ключ | По умолчанию | Описание |
|---|---|---|
| `species_whitelist` | `Human` | какие расы можно выбрать в редакторе персонажа, ID прототипов через запятую; пустая строка разрешает все с `roundStart: true` |
| `ooc_colors` | пусто | цвет ника в OOC по GUID, формат `"GUID=#RRGGBB, GUID=#RRGGBB"`; работает без Patreon |
| `ooc_colors_file` | `.CONFIG/ooc_colors.json` | те же цвета в JSON `{"GUID": {"color": "#RRGGBB", "name": "ник"}}`; сервер перечитывает файл раз в 5 секунд; важнее `ooc_colors` |

GUID игрока лежит в базе сервера: таблица `player`, колонка `user_id`.

## Вес админов

У каждого админ-ранга есть вес, он виден числом в панели прав (`permissions`).

- Админ с меньшим весом не может банить (и ролевым баном тоже), наказывать и применять админ-действия по ПКМ к админу с большим весом, а также редактировать его или его ранг. При равном весе можно.
- Хост (флаг `HOST`) весит больше всех.
- Менять вес можно в окне правки ранга, только с флагом `ADMINWEIGHT` и не выше собственного веса.
- Веса хранятся в `.CONFIG/admin_weights.json` (список `{ "Id": номер ранга, "Name": название, "Weight": вес }`), сервер перечитывает файл сам.
- По умолчанию у всех вес 0, то есть все равны.
- Кик (`kick`) это команда движка, весом его не ограничить.

Флаг `WEATHER` открывает окно погоды (`fecweather`, кнопка «Погода» во вкладке Admin abuse).

## Вайтлисты

Два независимых вайтлиста. Команды выполняются в консоли сервера или админом с флагом `Ban`.

### Вход на сервер (`[whitelist]`)

| Ключ / команда | Описание |
|---|---|
| `enabled = true` | пускает только тех, кто в списке (по умолчанию выключено) |
| `prototype_list = "basicWhitelist"` | правила из `Resources/Prototypes/whitelists.yml` |
| `whitelistadd <ник>` / `whitelistremove <ник>` | добавить / убрать |
| `kicknonwhitelisted` | выгнать тех, кого нет в списке |

### Должности (`game.role_whitelist`, по умолчанию `true`)

Закрыты без вайтлиста: командующий офицер, синтетик (и синтетики выживших), старший унтер-офицер-советник, главный инспектор и инспектор военной прокуратуры, командующий офицер выживших. В редакторе они показаны как «Закрыто».

| Команда | Описание |
|---|---|
| `jobwhitelistadd <ник> <ID>` | выдать доступ |
| `jobwhitelistremove <ник> <ID>` | забрать доступ |
| `jobwhitelistget <ник>` | посмотреть доступы |

ID должностей: `CMCommandingOfficer`, `RMCJobSynthetic`, `CMSeniorEnlistedAdvisor`, `CMProvostChiefInspector`, `CMProvostInspector`.

`role_whitelist = false` открывает эти должности всем.

## Сервер вне VS Code

```
dotnet run --project Content.Server -- --config-file .CONFIG/server_config.toml
```

Для собранного сервера путь задаётся относительно рабочей папки, либо положить файл рядом с exe под именем `server_config.toml`.
